Definition

What's an
AI agent?

A chatbot answers. An agent acts.

Three things, glued together by a loop:

01 An LLM that can decide what to do next.
02 Tools — named functions it can call on the outside world.
03 A runtime that runs the tools and feeds the results back.

That's it. The rest is plumbing.

§ 02 / FLOW
The Loop

One turn, in four steps.

01
Ask the model.
Send the whole conversation history plus the available tool schemas.
02
Read its reply.
If it's plain text — print it, done. If it's a tool call — keep going.
03
Run the tool.
Dispatch to a Python function, hit Jira, capture the result.
04
Loop back.
Append the result to history, go back to step 1. Cap at 6 iterations.

The next ten slides are the same loop, slowed down so you can see each frame.

STEP 01 — INPUT

The CLI.
Where words come in.

cli.py is the simplest piece. A while True over input(), with readline patched in so the up-arrow recalls previous lines.

It doesn't know anything about LLMs or Jira. It just gives every line to Agent.chat() and prints whatever comes back.

// observer pattern
Agent.chat() itself never prints. The CLI passes an on_tool_call callback when it constructs the Agent, and the agent invokes it after every tool result — that's where the -> and <- trace lines come from. Swap in a different UI, swap in a different callback. 
# cli.py — the entire REPL
while True:
    user_input = input("> ").strip()
    if not user_input:
        continue
    if user_input in {"/exit", "/quit"}:
        break
    reply = agent.chat(user_input)
    print(reply)
// blank line ⇒ no-op (matches python repl)

§ 02 / FLOW · STEP 02
STEP 02 — DECIDE

The Agent loop.
The heart of it all.

Every chat turn drives this loop. It runs until the model produces a plain-text reply — or hits the safety bound at six iterations.

Conversation history lives on the Agent instance. That's how multi-turn references — "add a comment to that bug" — work without any extra machinery. 

# agent.py — the loop, slightly simplified
def chat(self, user_message):
    self._messages.append(
        {"role": "user", "content": user_message}
    )
    for _ in range(6):   # MAX_ITERATIONS
        resp = self._llm.chat(
            self._messages, tools=TOOL_SCHEMAS
        )
        self._messages.append(_to_dict(resp))

        if not resp.tool_calls:
            return resp.content     # done

        for tc in resp.tool_calls:
            result = dispatch(tc.name, tc.args, self._jira)
            self._messages.append(
                {"role": "tool", "content": json.dumps(result)}
            )
// every loop iteration: ask, branch, dispatch, append

§ 02 / FLOW · STEP 03
STEP 03 — ASK

The LLMClient.
One wrapper, any provider.

The official OpenAI Python SDK, pointed at whatever endpoint speaks the OpenAI tool-call wire format. By default: OpenRouter routing to Gemma 4 31B running in Google AI Studio.

Want vLLM, Ollama, Together, Groq, or a Llama instead? Edit two lines of .env. No code changes.

// .env
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=google/gemma-4-31b-it:free 
# llm.py — the entire client
from openai import OpenAI

class LLMClient:
    def __init__(self, config):
        self._client = OpenAI(
            api_key=config.llm_api_key,
            base_url=config.llm_base_url,
        )
        self._model = config.llm_model

    def chat(self, messages, tools=None):
        resp = self._client.chat.completions.create(
            model=self._model,
            messages=messages,
            tools=tools,
            tool_choice="auto",
        )
        return resp.choices[0].message
// "openai-compatible" is the lingua franca of tool-calling

§ 03 / TOOLS · STEP 05
STEP 05 — DISPATCH

tools.py.
Two halves, one purpose.

TOOL_SCHEMAS — JSON Schema for each tool. Sent to the LLM every turn so it knows what's callable.

dispatch() — runs the tool. Catches every exception so the chat history never ends up with an orphan tool call.

// the envelope
Every tool returns {"ok": true, "result": ...} or {"ok": false, "error": "..."}. A consistent shape lets the model decide: retry, recover, or give up. 
# tools.py — the dispatch function
def dispatch(name, arguments, jira):
    handler = HANDLERS.get(name)
    if handler is None:
        return {"ok": False,
                "error": f"Unknown tool: {name}"}
    try:
        result = handler(jira, **arguments)
        return {"ok": True, "result": result}
    except JiraError as e:
        return {"ok": False, "error": str(e)}
    except Exception as e:
        # total: never leave an orphan tool_call
        return {"ok": False,
                "error": f"{type(e).__name__}: {e}"}
// 5 handlers: create · search · transition · comment · assign

STEP 06 — EXECUTE

The JiraClient.
One wire out, one wire in.

A thin httpx wrapper. One method per REST endpoint we care about. Sync, not async — for a single-user CLI it's easier to read and step through.

Plain Python strings in; structured Jira-shaped JSON out. The Atlassian Document Format (ADF) wrapping for descriptions and comments lives here so the LLM can keep using plain text.

// no MCP
Direct REST, deliberately. MCP adds a second process and another protocol — fine in production, noise in a learning project. 
# jira_client.py — assign an issue
def assign_issue(self, key, assignee):
    # resolve "me" / "unassigned" / search
    account_id = self._resolve_user(assignee)

    self._http.put(
        f"/rest/api/3/issue/{key}/assignee",
        json={"accountId": account_id},
    )
    return {"assigned": key}

§ 02 / FLOW · STEP 07
STEP 07 — CLOSE

The loop
closes.

The tool result is appended to history as a "role": "tool" message. The loop goes back to step 1 — another call to the LLM.

This time, with the tool result in context, the model almost always produces a plain text reply summarising what happened. The Agent returns it. The CLI prints it. Done.

// the guardrail
MAX_ITERATIONS = 6. Most turns finish in 1–2. Six is generous — and an absolute stop on a model self-correcting forever. 
# conversation history after one turn:
[
  {"role": "system", "content": "..."},
  {"role": "user",
   "content": "Assign SCRUM-6 to me"},

  # 1st LLM call → tool_call
  {"role": "assistant",
   "tool_calls": [{"name": "assign_issue", ...}]},

  # dispatch() ran it
  {"role": "tool",
   "content": '{"ok": true, "result":
              {"assigned": "SCRUM-6"}}'},

  # 2nd LLM call → plain text → done
  {"role": "assistant",
   "content": "Assigned SCRUM-6 to you."}
]
// history grows on the Agent instance, one turn at a time

§ 03 / TOOLS · IDEAS
Why It Works

Two design ideas
do all the heavy lifting.

01
A standard wire format.
Almost every modern LLM — OpenAI, Anthropic via aggregators, Llama, Qwen, Gemma, DeepSeek, Mistral, models hosted on vLLM or Ollama — speaks the OpenAI tool-call shape. Tools in, tool_calls out.

That makes the LLM a swappable part. Change two lines in .env and the agent talks to a different brain.
02
Tool calls are the world.
The LLM only ever describes what it wants done — it never executes anything itself. The runtime executes. The LLM sees the result.

Everything an agent can do is what its tools allow. Want a new capability? Add a tool. Want a sharper safety boundary? Remove one. The blast radius lives in tools.py.

§ 04 / SAFETY
Sharp Edges

Real Jira. Real writes.
So a few guardrails.

01
dispatch() is total. Every exception is caught and wrapped in {"ok": false, ...}. An uncaught error would leave the chat history with an orphan tool call and break the next turn.
02
Untrusted Jira data is delimited. Free-text fields (summaries, comments, display names) are wrapped in <untrusted>...</untrusted> before the model sees them. The system prompt tells the model: data only — never instructions.
03
Friendly errors enable self-correction. A wrong transition name produces an error that lists the valid options. A strong model reads it and retries with the right one — turning a 400 into a recovery opportunity.
04
Out of scope for v1: write confirmation. Writes fire immediately. Defensible for a single-user sandbox where every tool call is visible in the trace; the first thing to add before this ever runs unattended or on a shared instance.
